CELLA

An independent, high-performance spreadsheet, built in Rust

Contents· Source ↗· Documents ↗· Colophon

A feature in six chapters · the measured-performance release

For data sets, for agents, and for the files people actually send.

Cella is an independent, high-performance spreadsheet built in Rust — native on macOS, Windows, Linux and BSD, in the browser via WebAssembly. The goal is parity with Microsoft Excel, and superiority in speed, openness, and agent control. Version 0.13 is the release where the performance claims became measurements; this page reports them the way the project keeps them: with the harness, the comparison, and the gate.

01

Why another spreadsheet

Spreadsheets are where the work actually lives: the budget, the export, the invoice that arrived this morning. The files come in whether or not the tool can read them, and every year the tool is asked for more — more rows, more formats, more programs doing the driving. Cella is built for that world, and its positioning line says so without decoration: for data sets, for agents, and for the files people actually send.1

1 The positioning line is the README’s, verbatim. — README.md

It is an independent spreadsheet written in Rust — one codebase, compiled natively for macOS, Windows, Linux and the BSDs, and again to WebAssembly for the browser. There is no closed core: the repository is the product, the licence is MIT OR Apache-2.0 at your option, and the architecture is enforced by the build itself: the user-interface crate is swappable, and a cargo task verifies the layering, so that nothing below the interface can quietly grow a dependency on a windowing toolkit.2

2 The layering rule is a checked task, cargo xtask layers; the UI crate is swappable by design. — docs/architecture.md

The ambition is stated plainly: parity with Microsoft Excel — the ribbon verbs, the file formats, the function catalog — and superiority in the three places where a spreadsheet can be superior: raw speed on large workbooks, openness of source and of measurement, and control by programs rather than only through a graphical interface. The comparison is made against the real application, black-box, and the results are published in the repository for anyone to re-run.3

3 Clean-room, in the project’s words: Excel is observed black-box — synthetic workbooks in, screenshots out — and never read. — AGENTS.md

Exhibit A — the three commitments

For data sets
The query pipeline — a database file or a URL as a source — Parquet, the DAX data model, PivotTables and PivotCharts. A million-row workbook is a first-class citizen, and chapter three shows the memory bill.
For agents
Every user-visible action is a command; the MCP server, the CLI and the control channel reach all 438 of them. Chapter five runs a whole session in three lines.
For the files people actually send
.xlsx with everything that travels inside it, legacy .xls including its charts and shapes, password-protected packages, CSV and TSV — read, written, and kept faithful. Chapter two carries the evidence.

02

The files people actually send

The first test of a spreadsheet is not what it can build but what it can open. Real files arrive exported, forwarded, zipped, encrypted, and made in versions of tools that have since moved on. Cella treats the formats that reach people as the mainline of the product, not as import filters bolted to the side of it.

The mainline format is .xlsx: styles, tables, charts, PivotTables, conditional formats, validation, comments, slicers and timelines are read and written — and the parts Cella has not yet modelled pass through untouched, so saving someone else’s file does not quietly discard someone else’s work.4 Legacy .xls is read whole, embedded charts and shapes included. Password-protected packages — both the Agile and the Standard encryption — open and save. CSV and TSV come in on the daily path, PDF export and printing go out, and there is a JSON workbook of Cella’s own whose versioned envelope keeps unknown fields for the next reader.

4 What each format still lacks is kept ranked, with the rest of the work queue, in docs/file-format-parity.md.

Fidelity here is claimed with evidence, not adjectives. On 3 November 2026 a real-world corpus ran through the reader: 3,084 workbooks opened with no reader failure; 635 save-and-reopen cycles produced zero mismatches; and when Excel 16 was shown Cella’s copies it found them identical — sixteen .xlsx files compared cell for cell, and all thirty-seven readable .xls conversions matched.5

5 Logged in the progress log under 2026-11-03: 3,084 opened, 635 saved, zero mismatches. — ROADMAP.md

03

Speed, measured

Performance is a product feature at Cella, which means it is a number with a harness attached. The reference workbook is 1,000,000 rows by 6 columns — 72 MB on disk, two million formulas, the shape of a real export rather than a synthetic grid — and the program that measures it ships with the source.6

6 1,000,000 rows × 6 columns, 72 MB as .xlsx — “the shape of a real export, not a synthetic grid.” — docs/performance.md

Version 0.13 is the measured-performance release: sixteen changes in a single day, each measured before and after on the same machine, two of them reverted and re-landed when the numbers disagreed with the intuition.7 The day’s ledger, for the reference workbook:

7 Two of the sixteen were reverted and re-landed on measurement. — ROADMAP.md, 2026-11-18

The incumbents get the same file. One 70 MB workbook, one development machine, release builds all around:8

8 Excel 16.0.20527 and WPS 12.1.0.25222, one 70 MB file, release builds, the same development machine. — ROADMAP.md

None of it is folklore, because none of it is allowed to become folklore. The perf gate runs the eleven scenarios at 100,000 and 1,000,000 rows and compares every reading against budgets checked into the repository; a scenario that comes in over budget is measured once more, and if it is still over, the release fails.9 In 0.13.0, all twenty-two scenario rows finished within budget.

9 Budgets live in xtask/perf-budgets.txt; an over-budget scenario is re-measured once, then the run fails. — docs/performance.md

04

Open by construction

A spreadsheet holds numbers people are paid to be right about, so the project’s first rule outranks its feature list: never crash.

The rule is enforced by the compiler before it is enforced by review. The crates deny unwrap, expect and panic outright, and unsafe code is forbidden entirely; errors travel as Result values through each crate’s own error type.10 Numbers that arrive from the outside — file sizes, formula nesting depth, command parameters — are treated as hostile: checked arithmetic, bounded recursion, capped allocations, evaluation budgets, so a hostile formula becomes an error value in a cell rather than an aborted process.

10 The lints are denied crate-wide: clippy::unwrap_used, clippy::expect_used, clippy::panic, and unsafe_code = forbid. — AGENTS.md

The proof is a suite of 2,136 tests, but the interesting half is the fuzzing: every command is invoked with empty parameters, to prove that nothing assumes a graphical caller, and random command sequences are replayed against undo/redo, XLSX round-trip and full-recalculation invariants. Every fuzzer run records its seed, so a failure found at three in the morning replays exactly at nine.11 Beneath everything sits a last-resort guard — if a panic ever escaped, the session catches it and restores the workbook — which the project describes, honestly, as a safety net and not a licence.

11 The fuzzer is crates/engine/tests/command_sequence_fuzz.rs; every run’s seed is recorded for exact replay.

Openness goes past the licence. Every known shortfall is ranked in a public ledger; every asset carries a row in an attribution file, with a cargo task enforcing it; every layering rule is a checked task, not a paragraph in a wiki. A repository that publishes its own homework is easier to trust than one that promises.

05

Built for agents

Every user-visible action in Cella is a command — an object with an id, a label, a ribbon path, a shortcut, a documented parameter list and an enabled state. Bold is home.bold; a descending sort is data.sortDescending; writing one cell is cell.set. There are 438 commands, and a program can reach every one of them.12

12 engine.commands lists every command with its id, label, ribbon path, shortcut and parameter documentation. — docs/control-protocol.md

Three doors lead to the same set: an MCP server for agents, a CLI for scripts, and a JSON control channel for driving the live application. Nothing is graphical-only and nothing is automation-only — the command a person clicks from the ribbon is the command a program sends down the wire.

Programmatic calls never open dialogs: invoked with empty parameters, a command either runs with defaults or returns an error, and only a menu-style invocation shows a person anything at all. The channel keeps a replayable journal of commands already run (passwords excluded), lists every command with its documentation on request, and can screenshot the running window — which is how the project’s own examples render the interface offscreen for tests.13

13 “The interface has no motion: the selection outline and the zoom jump to where they are going.” — docs/control-protocol.md

The user interface is a client of the engine, and so is everything else. That is the whole agent story, told in one sentence.

06

Status, and what is next

Cella is at version 0.13.0, stage alpha, and the stage is stated with the evidence attached: the six core workflows pass end to end on macOS with save and reopen; the large-workbook gate for beta is met; the real-world corpus has run. What is left before the beta is hygiene rather than features — pinning the corpus for continuous integration, and a stability soak on the Windows GPU machines behind the field crash reports.

The project keeps a scorecard of itself, and it is not a generous one:14

14 The method and weights are published, and the table is re-measured, not copied forward. — docs/target-app-parity.md, ROADMAP.md

Some things are not built on purpose, each a dated decision rather than an omission: Python cells, equation layout, a twelve-language catalogue, real-time collaboration, mobile clients, an in-app assistant.15 The two languages that are built — English and Simplified Chinese — are built deliberately deep: all 504 user-visible labels are translated, and the Chinese interface was verified in the running application, surface by surface.

15 Each refusal is a dated decision in docs/roadmap.md — a record, not an apology.

What is next is written down in order, in public: the one-page summary in ROADMAP.md, the execution queue and its decisions in docs/roadmap.md, and every known shortfall ranked in docs/gaps.md. Pick a gap, land it with its test, and the gate runs. That is how this repository works.
