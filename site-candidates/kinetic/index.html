Why Cella

Built for the work that actually lands in your inbox.

Most spreadsheets assume you made the file. Cella assumes someone sent it — with a pivot table inside. It is a clean-room spreadsheet written in Rust, native on four platforms plus the browser, and every performance number it claims was measured and published.

For data sets

A spreadsheet that keeps up when the sheet keeps growing. The reference workbook — 1,000,000 rows × 6 columns, two million formulas — lives in 0.971 GB of heap, and one edit that recalculates a million chained formulas takes ~400 ms. The query pipeline pulls from a database file or a URL; Parquet, the DAX data model, PivotTables and PivotCharts are built in.

For agents

Every user-visible action is a command — bold a range, sort a table, insert a chart, protect a sheet. The MCP server, the CLI and the control channel all reach the same command set, and a programmatic call never opens a dialog: with empty parameters it runs with defaults, or tells you why not.

For the files people actually send

The formats that actually arrive. Reads and writes .xlsx — styles, tables, charts, PivotTables, conditional formats, validation, comments, slicers and timelines — and passes through what it does not model. Reads .xls including its charts and shapes, opens password-protected packages, and speaks CSV/TSV, its own JSON workbook and PDF.

Agents & commands

Everything is a command.

The ribbon, the CLI, the MCP server and the control channel are four doors into one engine. A programmatic call never opens a dialog — with empty parameters it runs with defaults, or returns an error. The journal records every command run, replayable, and document.inspect reports sheets, used ranges, tables, charts and names.

MCP server

cella-cli mcp speaks Model Context Protocol on stdio — headless by default, or --connect 7979 to drive the app that is already open. Tools include read_range, write_range, format_range, sort_range, insert_chart and evaluate_formula.

CLI

cella-cli eval '=SUM(1,2,3)' evaluates headless; cella-cli run --in book.xlsx --cmd 'home.bold={"range":"A1:C1"}' --out styled.xlsx applies commands and saves; cella-cli commands lists every command with its parameter docs.

Control channel

cella --control 7979 answers newline-delimited JSON on 127.0.0.1: engine.execute runs any command, sheet.read reads ranges, ui.screenshot returns a PNG. The full protocol lives in docs/control-protocol.md.

Never crash

“People trust Cella with their numbers; a crash loses their work.”

This outranks feature work. It is written into the crate lints, not just the docs — and every crash fix lands with a regression test.

  • No panics in non-test code.

    No unwrap, no expect, no todo! — and unsafe is forbidden outright, crate by crate.

  • Errors are Result<T, E> throughout.

    Every layer that touches a file, a formula or a command returns errors; input-derived numbers are treated as hostile — huge ranges and hostile formulas get an error value, never an abort.

  • 2,136 tests, plus fuzzing.

    Random command sequences run against undo/redo, XLSX round-trip and full-recalc invariants, and a dedicated pass makes sure every command survives empty parameters.

  • A last-resort guard.

    If a panic ever escapes, Session::execute catches it and restores the workbook. A safety net, not a licence.

Quick start

Run it from a checkout.

Everything runs from source with a Rust toolchain — the desktop app, the headless CLI, the MCP server and the offscreen renderer. The same code builds for the browser via WebAssembly (cargo xtask wasm).

cargo run --release -p cella -- --sample sales                          # the desktop app
cargo run --release -p cella -- --sample sales --control 7979         # + control channel
cargo run -p cella-cli -- eval '=SUM(1,2,3)'                          # headless evaluation
cargo run -p cella-cli -- mcp                                        # the MCP server on stdio
cargo run -p cella-ui-egui --example snapshot -- --sample sales out.png # offscreen render

Status & roadmap

Alpha — with the large-workbook beta gate met.

Version 0.13.0 was the measured-performance round: sixteen changes in one day, each measured before and after on the same machine and gated. 100 million cells open at 16.7 MiB live / 183 MiB peak. A real-world corpus run opened 3,084 workbooks with no reader failure and 635 save/reopen cycles with zero mismatches. What is left for beta is the release run and pinning that corpus for CI — every remaining gap is ranked in public.
