CELLA For data sets, for agents, and for the files people actually send.

A clean-room spreadsheet that runs natively on macOS, Windows, Linux and BSD — and in the browser via WebAssembly. The goal is Microsoft Excel parity, and superiority where it counts: speed, openness, and control for the programs that drive it.

SECTION A

WHY CELLA

A / G

Four commitments, each one verifiable in the repository. The drawing references the machine; nothing on this page is marketing.

A1

THE FILES PEOPLE ACTUALLY SEND

Real workbooks arrive as .xlsx with styles, tables, charts and PivotTables; as legacy .xls; sometimes encrypted. Cella reads and writes all of them — and the parts it does not model yet pass through untouched, instead of vanishing on save.

A2

PERFORMANCE IS MEASURED, NOT CLAIMED

Every number on this page comes out of a harness: a 1,000,000-row reference workbook, best-of-three passes, and a budget gate that fails a release on regression. The results are in SECTION C; the method is in docs/performance.md.

A3

EVERY ACTION IS A COMMAND

There is no scraping layer between a program and the app: 438 commands cover the ribbon, and the MCP server, the CLI and a JSON control channel drive the identical set. An agent calls home.bold the same way you click it.

A4

CLEAN-ROOM, OPEN, RUST-NATIVE

MIT OR Apache-2.0, at your option. No code borrowed from other suites — behaviour comes from public documentation and black-box observation. A layered Rust core with a swappable UI, and a WebAssembly build that is gated, not aspirational.

With OpenGL as the Windows default: the window is 183 MB lighter at the same 144 Hz.

C-05

THE HARNESS AND THE GATE

One command reproduces every number above, best of three passes — and a budget gate turns the table into a release requirement: cargo xtask perf compares each scenario against xtask/perf-budgets.txt and exits non-zero on a regression. It runs before every release and after any hot-path change, deliberately outside per-commit CI.

RUN IT YOURSELF
# reference workbook, machine-readable, best of three
cargo run --release -p cella-engine --example perf -- 1000000 --json --repeat=3

--release is not decoration: a debug build is 10–30× slower, and the harness says so.

SECTION D

EVERY ACTION IS A COMMAND

D / G

438 commands cover the ribbon at 0.13.0 — each with an id, a label, a ribbon path, a shortcut, a params doc and an enabled state. Three transports drive the identical catalog, and programmatic calls never open dialogs: empty params run with defaults, or return an error.

D1 · MCP SERVER

FOR AGENT FRAMEWORKS

stdio, the standard MCP transport — the same command set an agent sees in its tool list.

# the MCP server on stdio
cargo run -p cella-cli -- mcp
D2 · CLI

HEADLESS

Evaluate a formula, or run commands over a workbook and write it back out — no window, no UI.

# headless evaluation
cargo run -p cella-cli -- eval '=SUM(1,2,3)'
D3 · CONTROL CHANNEL

THE LIVE APP

Newline-delimited JSON to 127.0.0.1:7979 while the app runs — pointer, keyboard, dialogs, even ui.screenshot for visual verification.

# desktop app + control channel
cargo run --release -p cella -- --sample sales --control 7979
D4

DISCOVERY

  • engine.commands returns the full catalog — search included
  • Each entry: id, label, ribbon path, shortcut, params doc, enabled
D5

REPLAY

  • engine.journal replays the session's commands
  • Passwords are never journaled
  • Capped at 10,000 entries and 64 MB
D6

NO DIALOGS

  • Empty params run with defaults or return an error
  • Only menu-style invocation opens a dialog
  • ui.screenshot returns a PNG, base64 when no path
SECTION E

NEVER CRASH

E / G

People trust Cella with their numbers; a crash loses their work.

THE ENGINEERING STANDARD — DENIED BY LINT IN EVERY CRATE, PROVEN BY FUZZING
E1

THE POLICY

No panics in non-test code: unwrap, expect, panic!, todo! and unreachable! are denied by lint in every crate, and unsafe is forbidden outright. Errors are Result<T, E> end to end, through each crate's own error type.

E2

HOSTILE INPUT

Files, formulas and command parameters are hostile numbers: checked and saturating arithmetic, capped allocations for huge ranges, bounded recursion — and evaluation budgets for nesting, work and LAMBDA fuel behind an 896 KiB stack guard. A hostile formula is an error value, never a process abort.

E3

THE PROOF

2,136 tests, and a command-sequence fuzzer replaying random sequences against undo/redo, XLSX round-trip and full-recalculation invariants. The real-world corpus run: 3,084 workbooks opened, zero reader failures; 635 save/reopen cycles, zero mismatches — Excel 16 found Cella's copies identical.

E4

LAST RESORT

Session::execute catches anything that escapes and restores the workbook. It is a safety net for the user's data — never a licence for the code.

SECTION F

PLATFORMS & QUICK START

F / G
F1

NATIVE

One Rust core, native windows on macOS, Windows, Linux and BSD, with per-platform chrome. On Windows, OpenGL is the default renderer — a 183 MB lighter window at 144 Hz.

F2

BROWSER

The WebAssembly build is a gate, not a stretch goal: cargo xtask wasm runs in CI, so the browser target is never broken.

F3

LANGUAGES

English and Simplified Chinese, deliberately two: all 438 command labels are translated and verified in the running app. Formulas stay en-US — exactly as in Microsoft's own Chinese build.
