A:> why cella

A spreadsheet built like an engine room: every claim is measured, every action is a command, every file you are sent just opens.

  1. THE FILES PEOPLE ACTUALLY SEND

    The .xlsx a colleague exports at 4:59 p.m., the legacy .xls with its charts and shapes, the password-protected package, the CSV your pipeline produces: they open. Styles, tables, PivotTables, conditional formats, validation, comments, slicers and timelines are read and written — and the parts Cella does not model yet pass through untouched instead of being dropped.

  2. MEASURED, NOT MARKETED

    Every number on this page comes off a harness — crates/engine/examples/perf.rs — with a budget file and a release gate that fails on regression. The table below is not a claim; it is the measurement, attributed to the machine it ran on.

  3. EVERY ACTION IS A COMMAND

    The ribbon you click and the protocol an agent speaks are the same command set — 438 commands, from home.bold to data.sortAscending to cell.set. Nothing is UI-only: if you can click it, a program can run it, and it never opens a dialog on the programmatic path.

  4. OPEN AND CLEAN-ROOM

    MIT OR Apache-2.0, written in Rust. Behaviour is measured against Microsoft Excel only by black-box observation — never by copying it. Cella is an independent, modified version of GridCraft: credited, not disguised, and never presented as an ArtCraft product.

B:> capabilities

  1. FILES

    Reads and writes .xlsx — styles, tables, charts, PivotTables, conditional formats, validation, comments, slicers and timelines, with pass-through of unmodelled parts. Reads .xls including its charts and shapes. Reads and writes password-protected packages. CSV/TSV, Cella's own JSON workbook, PDF export and printing.

  2. CALCULATION

    500+ Excel functions, dynamic arrays and spills, LET/LAMBDA, tables and structured references, iterative calculation, multi-threaded recalculation.

  3. DATA

    The query pipeline — a database file or a URL as a source — Parquet, the DAX data model, PivotTables and PivotCharts, slicers and timelines.

  4. AGENTS

    Every user-visible action is a command, and the MCP server, the CLI and the control channel all reach the same set. Programmatic calls never open a dialog.

  5. INTERFACE

    English and Simplified Chinese, key tips, keyboard context menus, an accessibility tree, and an offscreen snapshot renderer for tests.

The cascade you just saw is the chain shape the real engine walks — a million formulas deep, in ~400 ms. This demo's evaluator is deliberately tiny and safe: no eval(), a 120-character cap, bounded recursion and a step budget — a hostile formula becomes an error value, never a crash. The real engine is held to the same rule at a slightly larger scale.

E:> agents & commands

Everything a user can do, a program can do. Every user-visible action is a command — 438 of them — and the MCP server, the CLI and the control channel are all front doors to the same set.

$ cella --control 7979
$ {"id":1,"method":"engine.execute","params":{"command":"cell.set","params":{"cell":"B2","input":"=SUM(A1:A9)"}}}
← {"id":1,"ok":true,"result":{"cell":"B2",…}}
$ {"id":2,"method":"home.bold","params":{"range":"A1:C1"}}
← {"id":2,"ok":true,…}
# newline-delimited JSON on 127.0.0.1:7979 — any command id is a method name
# programmatic calls never open a dialog: empty params run with defaults or error out

CONTROL CHANNEL

Run the app with --control 7979 and speak newline-delimited JSON to 127.0.0.1:7979. Drive input, the ribbon, dialogs, even ui.screenshot — and read the workbook back. docs/control-protocol.md ↗

CLI

Headless and scriptable: cella-cli eval '=SUM(1,2,3)', cella-cli run --in book.xlsx --cmd 'home.bold={"range":"A1:C1"}' --out book.xlsx. docs/cli.md ↗

MCP SERVER

cella-cli mcp serves the Model Context Protocol on stdio: an agent lists the commands, runs them, inspects state — the same commands the ribbon runs. docs/mcp.md ↗

F:> never crash

People trust Cella with their numbers; a crash loses their work.

  1. NO PANICS IN NON-TEST CODE

    No unwrap, no expect, no panic!, no unreachable — and no unsafe anywhere: unsafe_code = "forbid". Errors are Result<T, E> from the file reader to the command layer, enforced by lints that deny the escape hatches.

  2. HOSTILE INPUT IS TREATED AS HOSTILE

    Input-derived numbers are assumed to be out to get you: checked and saturating arithmetic, capped allocations for huge ranges and whole-column formulas, bounded recursion for nesting, dependency chains and names that refer to names. Evaluation budgets turn a hostile formula into an error value, never a process abort.

  3. 2136 TESTS + COMMAND-SEQUENCE FUZZING

    Every command is fuzzed with empty parameters; random command sequences are replayed against undo/redo, XLSX round-trip and full-recalc invariants. Soak runs replay from durable seeds. The full suite is the commit gate, not an afterthought.

  4. A LAST-RESORT GUARD, NOT A LICENCE

    If a panic ever escapes, Session::execute catches it and restores the workbook. It exists so that the worst day is a bad surprise, not lost work — and it is treated as a bug, every time.

The standard is public: the never-crash rule is a standing repo policy with a regression test attached to every fix. craftrules/standards/never-crash.md ↗

G:> platforms & quick start

NATIVE ▸ MACOS · WINDOWS · LINUX · BSD   BROWSER ▸ WEBASSEMBLY. Alpha stage: built from source, straight from the README.

cargo run --release -p cella -- --sample sales                        # the desktop app
cargo run --release -p cella -- --sample sales --control 7979         # + control channel
cargo run -p cella-cli -- eval '=SUM(1,2,3)'                          # headless evaluation
cargo run -p cella-cli -- mcp                                        # the MCP server on stdio
cargo run -p cella-ui-egui --example snapshot -- --sample sales out.png   # offscreen render

--release is not optional for the first command: a debug build is 10–30× slower, and the perf harness says so, politely. The sample workbook — File → New → Sample — is a quarterly sales dashboard with live charts.
